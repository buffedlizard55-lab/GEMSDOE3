# Starting point for every session

1. Read `README.md` in full, including the preserved user brief. Then read `NEXT_STEPS.md`, `evidence/review.json`, and the latest `docs/data/experiment.json` / `docs/data/feed.json` if present.
2. Maximize P(Win): prioritize evidence about discovery/generalization and a valid, reproducible submission over optimistic presentation or surrogate-score chasing. Own the Outcome: run the pipeline, inspect the bytes, surface failures, and leave useful next steps.
3. Never claim a leaderboard gain, a hidden-label score, an official upload, or a successful deployment without direct evidence. A local/proxy metric is not a competition result. Do not equate a public user score with a particular artifact unless its submission identity is known.
4. Use official primary sources; every factual external claim needs a source link and checked timestamp. Separate source retrieval, exact-claim verification, inherited evidence, measured data, hypotheses, and unavailable evidence. Preserve last-success timestamps on failed refreshes.
5. Read `legacy/STATUS.md` and `legacy/SUGGESTIONS.md` for historical work. `legacy/` is a pinned copy, not the active pipeline. Its old claims and automation are historical; do not execute workflows that push to the upstream repository.
6. Every candidate must pass strict read-back GeoTIFF validation against the supplied template: identical CRS, shape and affine transform; one float32 band; finite [0,1] inside the valid mask; NaN outside; NaN nodata; no hidden internal masks. Reject corrupt or nonfinite predictions; do not silently clip away model defects in the exporter.
7. Keep spatial training, tuning and audit partitions distinct. Never use proxy or test labels as prediction features. Freeze the recipe before reading the audit results. Clearly disclose limits of incomplete-label evaluation.
8. Use three explicit passes: implementation + execution; adversarial bug/edge-case review; full-request and reproducibility recheck. Record actual commands/results in evidence, not invented test counts.
9. Large data, models and caches stay outside Git. `scripts/download_competition_data.sh` restores hash-pinned public inputs; an already configured GitHub CLI is the fallback when raw HTTPS is blocked. Never request manual tokens. Preserve provenance, hashes and small evidence. Do not leak secrets into logs or manifests.
10. Work on the session's assigned branch. Never push automation directly to main. Use pull requests and respect checks. GitHub Pages must work under `/GEMSDOE3/` and previews on 0.0.0.0; browser requests must be relative URLs.
11. DrivenData enrollment, legal eligibility, final selection, AI disclosure and authenticated upload are human/account-bound steps. Do not simulate them or ask for passwords/tokens in chat.
